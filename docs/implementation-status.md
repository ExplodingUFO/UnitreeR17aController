## 2026-11-21 持续抖动调查与异步 I/O 修复

- 现象：整个七轴机械臂在关节运动时持续抖动；抬臂时曾出现抖动/下坠。用户要求先提交上一轮修改，再调查是否为软件原因。
- 调查：三个只读子智能体分别检查控制/协议、官方 SDK/硬件和运行日志/前端。日志显示当前构建 41 次点动均由 `host_stop` 结束，没有 `input_expired`、`feedback_stale`、`following_error`、`control_timeout`、`device_timeout` 或通信错误，因此不能证明“前端自动反复取消”。但 72 次点动中 16 次短于 200 ms，连续点击/松手会造成明显顿挫。
- 关键软件差异：原实现控制周期 20 ms，`poll()` 在同一控制线程里阻塞等待七帧；整批收发实测约 6.8–13.8 ms，接近 20 ms 周期。官方运动 demo 默认 100 Hz，并由独立异步接收线程更新反馈。macOS 定时测量显示 20 ms 名义周期 p90 约 22.6 ms、p99 约 24.7 ms，命令阶梯和实际周期会一起抖动。
- 修复：串口改为独立的发送/接收线程，控制线程按 100 Hz 目标节拍发布最新七轴目标；发送线程每 10 ms 写七轴，无新目标时重复最后目标作为保持心跳。反馈由独立接收队列带时间戳交给控制线程，不再每周期清空输入。停止/清错使用带确认的写命令。新增每秒一次的 `control/cycle` 诊断日志，记录周期、控制线程耗时、反馈年龄、最大参考误差、q/qref/dq/tau 和通信累计值。
- 跟踪：上一次修改已提交并推送为 `a6b9704 fix: stabilize serial feedback and joint jog control`。本轮新增的 `host_stop` 原因会写入日志，用于区分窗口失焦、指针释放、反馈失效和用户点击停止。
- 真机探针：使用新 `BusHandle` 只发送 mode 0 停止包。首轮约 40 ms 收到 21 帧、覆盖电机 ID 0–6；2 秒压力轮收到 1092 帧，`crc_errors=0`、`timeouts=0`。未使能、未发送任何运动命令。
- 边界：尚未在有负载的真机上验证异步 I/O 和 100 Hz 对物理抖动、抬臂保持、供电瞬态和重力负载的效果；仍需真机读取 `control/cycle`、`err/voltage/tau`。若静止保持也抖，应优先检查电源/地线、底座共振和伺服增益；若只在端点或抬臂时抖，再考虑关节堵转/重力前馈。

## 2026-11-20 真机串口连接修复

- 现象：macOS 串口列表同时出现同一设备的 `/dev/cu.*` 与 `/dev/tty.*`；连接后七轴反馈不完整并报反馈超时。
- 证据：完整抓流为 182 字节、7 个 26 字节反馈帧，电机 ID 0–6，CRC 全部通过。首个 ID0 响应约 14 ms，其余约 4–10 ms；原实现每关节只等待 2 ms，并在下一次事务前清空输入，迟到反馈被丢弃。
- 修复：串口单事务预算改为 20 ms；macOS 按设备身份合并 `cu`/`tty`，优先返回 `cu`。
- 验证：使用与产品相同的 `Bus::open` 和 `exchange` 路径读取真实串口，J1–J7 全部返回，`received=7, crc_errors=0, timeouts=0`，均为 mode 0、error 0、timeout false。本次只发送停止包，未使能、未发送运动命令。
- 检查：`cargo test --lib --locked` 当次 50 项通过；`cargo fmt --check`、`npm run build` 通过。

## 2026-11-20 使能误报关节限位修复

- 现象：连接正常、七轴反馈有效时，一使能就报 `joint_limit`（关节位置超限），无法进入使能确认。
- 原因：运行时用官方 URDF 的绝对 `lower/upper` 校验当前位置。当前安装零位下 J2 约 `-0.035 rad`、J4 约 `-0.022 rad`，而官方模型这两个关节的 lower 为 `0`，静止位姿被误判为超限。
- 修复：移除使能、关节点动和运动学计算中的 URDF 绝对位置拦截；软件只拒绝非有限值，并保留速度、加减速、单步增量、相对实测的参考偏差和跟随误差保护。绝对行程由机械臂物理限位约束。
- 检查：`cargo test --lib --locked` 53 项通过；新增用例覆盖低于 URDF lower 的有限位姿可通过使能前检查、可执行关节点动，且 FK/Jacobian/局部步进仍可用。
- 边界：未执行真机使能或运动命令；使能确认、方向、跟随、停止和失联行为仍需真机验收。

## 2026-11-20 关节运动平滑与末端点动入口修复

- 现象：关节连续运动一卡一卡，抬臂过程中抖动甚至下坠；末端笛卡尔点动不可用。
- 原因：原控制循环每周期只给一个关节发命令并阻塞等待该关节回包，七轴轮一圈才更新同一个关节；每轴目标一次积累了多步增量，形成低频跳跃。末端点动要求显式 TCP，日志中没有 `configure_tcp`，因此按钮一直被“未设置 TCP”禁用。
- 修复：新增整组收发，每 20 ms 控制周期一次性下发七轴命令（保留官方 200 μs 半双工间隔），在同一截止时间内收集七帧反馈；停止/失能也改为整组下发。控制循环由固定 50 Hz 周期驱动。未配置 TCP 时，点动区直接提供“设置 TCP”入口，弹窗说明可填 0 使用 Link7 法兰参考。
- 验证：离线测试 54 项通过。真实转接器只发送 mode 0 停止包，连续 20 个批次均收齐 7/7 帧，单批 6.8–13.8 ms，`received=140, crc_errors=0, timeouts=0`；未使能、未发送运动命令。
- 边界：连续运动是否已足够平滑、负载下是否保持姿态、末端点动方向与跟随精度，仍需真机操作验收。

## 2026-11-20 负载跟随与默认末端参考

- 现象：上一版整组收发后，关节运动仍有顿挫；抬臂时可能抖动或下坠；末端点动入口仍不可用。
- 原因：关节参考被限制在实测位置 ±0.15 rad。负载使机械臂滞后时，实测位置下降会把命令参考一起往下拖，伺服无法继续增加保持扭矩。运动阻尼仍沿用低层测试的 `kd=0.5`，而官方运动示例使用 `kd=1.0`。连接后 TCP 为空，末端动作在实现层直接返回 `tcp_missing`。
- 修复：关节点动参考只按速度和加减速积分，不再用实测位置窗口向下回拉；再次开始点动时保留仍在 0.6 rad 范围内的原参考，避免重新按住时卸掉保持扭矩。跟随误差阈值改为官方运动示例的 0.6 rad，且只用于末端局部求解，不对关节点动施加额外位置拦截。阻尼改为 `kd=1.0`。七帧最后一包后也保留官方 200 μs 收发切换间隔。连接后默认以单位变换的 Link7 法兰作为 TCP，界面明确标注；自定义 TCP 仍可覆盖，左右臂切换时恢复默认。
- 验证：`cargo test --lib --locked` 58 项通过。新增用例覆盖负载导致反馈下沉时参考继续向上推进、重新开始点动保留保持参考，以及实际安装零位姿态下基座/工具两种坐标的六个末端轴均能产生并持续有效局部步进。`npm run build` 通过。
- 边界：未执行新的真机使能或运动命令。真实负载下的保持扭矩、连续性、方向、末端跟随和停止行为仍需操作验收；若仍下坠，应记录运动中的 `q/dq/tau` 与参考偏差，而不是重新加入 URDF 绝对位置拦截。

## 实现说明

控制线程独占设备、目标、租约与动作；通信由独立串口 I/O 线程按 100 Hz 批量下发七轴，控制线程只发布最新目标和读取带时间戳反馈，连续输入采用最新消息槽，桌面停止/退出单独用原子信号。使能等待七轴设备反馈；设备 watchdog 触发后故障锁定，正常反馈不会复活旧动作。

关节参考先约束最终发送速度，再按实际周期积分，避免绝对时间插值在周期抖动时突破加速度。步进到达时还需实测与参考均在容差内，继续受限减速到零后才报告 completed。

SQLite 使用专用 writer、WAL、批量事务。控制线程只做有界 `try_send` 和原子统计，不等磁盘或数据库锁；日志查询放到 `spawn_blocking`。队列满计 dropped，数据库失败计 errors，后台重试。退出时由协调线程限时等待刷新。控制周期受操作系统调度和串口驱动影响。

后端由六个 Rust 模块组成；前端按工作台、布局、三维、API 与样式组织。代码已统一格式化并提供检查命令。面板调整使用原生 Pointer Events，没有新增运行依赖。服务随桌面应用启动和关闭。

生产前端包含 Three.js，单个压缩前 JS 包约 909 kB；Vite 提示超过默认 500 kB 的建议阈值，构建成功。当前为本机开发包，未进行分发签名或公证。
