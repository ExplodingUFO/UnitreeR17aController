# R1-7a 控制器首版规格（1.0）

状态：macOS arm64 软件版本已实现。更新日期：2026-11-21。构建与测试结果见[测试记录](implementation-status.md)，接口细节见[接口说明](implementation-contract.md)，技术选型见[架构设计](adr/0001-controller-architecture.md)，早期界面见[原型记录](prototype.md)。

## 1. 功能范围

首版是一个 Tauri 2 桌面应用：所在电脑经厂商 USB 转接器直连独立 R1-7a，Rust 后端处理设备与运动，同时向其它本机服务提供 HTTP/WebSocket。窗口关闭时后端一同结束。控制权唯一，显式释放或转交。

当前测试环境为 macOS arm64。真机、Windows 和 Linux 的测试项目见[测试记录](implementation-status.md)。

范围包括连接、状态、使能/停止、七轴关节和末端六维的连续/步长点动、基座/工具坐标、当前七轴局部运动学、实测模型、本机调用、短时采样、逐轴伺服调试与必要诊断。工作台始终可以取消当前动作，不取得控制权，也不自动失能。

首版不包含全局位姿搜索、任意轨迹规划、相机/点云、双臂/灵巧手、录制回放、图表平台、插件、无窗口驻留或局域网预留。

## 2. 技术选型

| 部分     | 确定方案                                                  | 职责                                                  |
| -------- | --------------------------------------------------------- | ----------------------------------------------------- |
| 桌面     | Tauri 2，React + TypeScript + Vite                        | 一个工作台、应用生命周期与本机能力                    |
| 三维     | Three.js + URDFLoader                                     | 加载官方 URDF/STL，使用实测关节值更新模型             |
| 通信     | serialport 4.10.1                                         | 跨平台串口；当前 IM6014 报文/CRC/标定由项目实现       |
| 数值     | nalgebra 0.35.0 + urdf-rs 0.10.0                          | 当前七轴 FK、TCP 几何 Jacobian、带动态约束的局部求解  |
| 本机接口 | Axum 0.8 系列 + Tokio                                     | HTTP 请求、WebSocket 状态；控制线程独立调度           |
| 数据     | serde/JSON；rusqlite 0.41.1（bundled）+ crossbeam-channel | SQLite 结构化事件日志，后台写入，有界队列隔离控制线程 |

以上为当前产品依赖基线，依赖清单和锁文件随产品保存；依赖解析与构建检查结果见[测试记录](implementation-status.md)。串口与数值版本依据现有研究；采用直接 nalgebra 路线的依据与验证责任见[数值评估](research/nalgebra-direct-assessment.md)。本机接口的实现依据为 [Axum 官方文档](https://docs.rs/axum/latest/axum/)。

Rust 后端位于 Tauri 应用中，本机接口不另起服务进程。前端所有设备动作与其它本机调用方进入同一控制模块；桌面程序退出和总停止也调用该模块，不另做一套运动逻辑。

桌面操作和状态读取使用本机 HTTP/WebSocket。Tauri 提供会话信息、桌面停止和退出请求三个命令，并管理应用关闭。两类接口调用同一个 arm 模块。

Tauri 命令只向打包的主窗口开放，不授权远程页面。开发与打包 WebView 的 Origin、CORS、CSP 和资源 URL 按本机访问配置；联调结果见测试记录。Tauri 的命令、窗口权限与 CSP 配置方式分别见[命令文档](https://v2.tauri.app/develop/calling-rust/)、[能力文档](https://v2.tauri.app/security/capabilities/)、[CSP 文档](https://v2.tauri.app/security/csp/)。

自定义 Tauri 命令由 AppManifest 管理权限，仅向 main 窗口开放。HTTP 客户端使用独立的会话认证和控制权检查。

窗口最小尺寸为 800×600。控制页同时显示连接、七轴反馈、3D、末端坐标和点动；日志默认收起。点动面板的“参数”按钮打开伺服调试弹窗，控制页保持原有设置与 3D 视角。“接口”页包含接入信息、接口参考和请求结果，顶部“日志”页提供完整日志与筛选。各页面保留停止按钮，切走控制页时结束连续点动。布局测量结果见测试记录。

控制页 3D 标题栏直接提供录制时长、录制/停止和“记录”按钮；“记录”打开最近录制与下载弹窗，不切页。录制默认 10 秒，可选 1–20 秒；端口已连接时可开始，无需控制权或使能。界面显示“控制参考 · 实际发送 · 关节反馈”、采样状态、样本/写入/待写/丢弃/错误数，完成或失败后可下载 JSON，写入中暂不可下载。“停止录制”只结束记录，工作台停止按钮继续负责取消机械臂动作。

伺服调试弹窗提供全局摩擦开关及 J1..J7 的阻尼、速度前馈权重和摩擦参数草稿，可恢复基线、显式应用或复制 JSON。关闭并重开保留本次连接的草稿和上次编辑位置，连接变化时重置草稿。打开弹窗结束按住连续点动；停止按钮持续可用，Esc 停止并关闭，Tab 焦点在弹窗内循环，关闭后返回入口按钮。编辑与恢复基线只更新草稿；取得控制权、连接就绪且无动作后才能应用。连接、断开均恢复后端基线，参数不自动持久化。

左右栏边界、3D/末端坐标区边界及日志上边界均可拖动，尺寸保存在本机，双击恢复对应项默认值。日志默认收起为 36 px，可展开或拖动调整；工作区至少 390 px，末端坐标区至少 128 px。窗口缩小或日志拉高时，关节表和点动列表允许内部滚动，各模块继续保留在当前页面。3D 画布跟随实际面板尺寸更新。

无设备时显示模型参考姿态，关节 q/dq/tau、反馈时间及计算 TCP 为 `null`，界面标注“参考模型/未连接”。

官方资源当前没有单独定义真实工具中心。连接后默认把 Link7 法兰作为末端点动参考并明确标注，它不表示已标定工具中心；安装工具后可用 `configure_tcp` 替换为实际偏移。末端点动要求当前模型、标定、反馈和动态限制有效，默认 Link7 参考已经满足这一入口条件。

配置按动作校验：关节点动要求当前模型、标定、反馈和动态限制有效；末端点动使用当前 TCP（默认 Link7 法兰）。设置自定义 TCP 后断开再以同一侧连接会保留该值，切换左右臂则恢复 Link7 默认参考。

## 4. 点动交互与控制状态

### 已确认的点动语义

- 同时包含 XYZ 平移和姿态旋转、基座/工具坐标、按住连续与固定步长。平移保持工具姿态，纯旋转绕当前 TCP。
- 七轴分别提供连续/固定角度关节点动；一次只执行一种关节或末端动作。关节点动直接生成受限关节参考，不经过 IK。参考按最终受限速度积分，并限制加速度及 jerk，不跟随实测位置向下回拉；再次开始点动时，若原参考仍在 0.6 rad 跟随范围内则保留，避免重新按住时卸掉保持扭矩。伺服基线采用 Unitree 官方 R1-7A 遥操作的 `kp=60`、`kd=10`，并按 URDF 在指令姿态计算重力前馈，逐轴限幅 ±8 Nm；绝对行程由机械臂物理限位约束。
- 后端以 100 Hz 目标控制节拍生成七轴参考；串口读写由独立 I/O 线程负责，控制线程只发布最新参考和读取带时间戳的反馈。发送线程保持原始 10 ms 截止时间网格，错过的槽位直接跳过，不补发、不因唤醒延迟或新参考重设网格；普通批次的主机起点至少相隔 5 ms。实际总线节拍仍受操作系统、USB/FTDI 和驱动调度影响。
- 连续点动松开、失焦、页面隐藏、输入失效或控制权失效时结束动作；服务端独立校验输入有效期。
- 固定步长每次形成一个平滑局部运动段，运动中拒绝新步长；不积压点击，也不自动重试运动请求。
- 从有效关节反馈开始，小步延续当前构型。首版不独立调肘；局部无法推进或接近约束时降速/停止并解释原因。
- 内部单位为米和弧度。UI 可以显示毫米/角度；姿态内部用四元数/旋转向量，显示 RPY 不决定控制算法。

保持姿态与固定步长以配置的位置/角度容差判定，并用 FK 复核候选结果。关节、末端与收纳返回共用离散参考的速度、加速度和 jerk 限制；当前关节上限为 0.20 rad/s、0.60 rad/s²、6 rad/s³，jerk 值为离线默认值。控制器保留原有 Euler 积分：`q_ref` 按最终速度与实际控制间隔积分，加速度和 jerk 从相邻参考速度、加速度计算。

发送端按本批次主机起点对最新源参考取样，源年龄要求 `0 ≤ age ≤ 50 ms`。速度按 `dq + ddq*age` 推至发送时刻，在关节速度上限或首次速度零点封顶。首次伺服取样的位置按同一段速度积分；后续位置为 `q_previous + 0.5*(dq_previous + dq_sample)*Δt_tx`，从上一成功整批目标连续积分，不随控制参考切换重新锚定位置。与源参考投影位置的偏离不得超过 0.01 rad；后续仍受目标、路径和实际发送间隔的速度检查。

末端局部求解把关节动态窗口直接纳入 Jacobian 的有界二次规划，在同一次求解中约束七轴速度，保持所选 TCP 方向和姿态。逐轴独立平滑 IK 结果会改变末端路径，因此候选在约束内统一求解并经 FK 复核；保留单步增量和相对实测的参考偏差限制。所选路径的模型偏差阈值为 50 μm、0.002 rad，接近全局 TCP 速度上限时预留 10% 目标余量，即 13.5 mm/s、0.135 rad/s；低于该阈值的请求不因这一余量额外缩放。最终 FK 仍检查 15 mm/s、0.15 rad/s 的硬上限。这些是模型检查阈值，硬件精度待测。关节点动不使用末端的相对位置窗口。

发送候选沿用动作的不可变 TCP 与路径起点，复核路径、全局 TCP 速度、相对实测偏差、上一成功写完整批的伺服目标及当前目标边界。相对上一成功目标的关节位移同时受 0.01 rad 和 `JOINT_SPEED × 实际发送间隔` 限制；两端速度同向时，位置不得反向变化，否则按 `constraint` 保持或拒绝。写入前复查 epoch 和输入/租约有效期；失效的候选不提交。已开始写入的七轴批次仍沿用原有 20 ms 整批预算，不在批次中途插入停止报文。

新点动、固定步长和收纳回程统一从当前 generation/epoch 的成功静止发送目标建立起点，要求七轴指令零速、批次年龄不超过 50 ms，避免积分残差跨动作累积。尚未确认时拒绝新动作并返回 `motion_busy`，不积压请求；相对实测偏差仍不得超过 0.6 rad。

参考过旧、来自未来、无效或违反约束时，若有上一成功整批伺服目标，则保持其位置、速度置零。控制器只处理 generation 与 epoch 仍匹配的拒绝，将当前动作记为 `failed/send_reference`，保留控制权；已使能时继续保持使能。使能确认中的匹配拒绝会结束 `enable_request` 并记录 `failed/send_reference`，维持 `enabled=false`，同次新鲜反馈不能再使其进入 Ready。迟到拒绝不影响新动作。首次无效且没有成功伺服历史时走 I/O 错误处理。

正常停止继续受 jerk 限制减速，可能比此前需要更长时间。停止求解惩罚关节速度本身，使冗余方向的速度也减至零，连续性由导数硬约束维持。笛卡尔路径上无法继续制动时，记录 `stop_path` 并转为受限关节制动；故障、失能和关闭仍优先处理。同一源参考可以在不同发送时刻取样，尚未发送的更新也可合并；控制器导数约束不保证实际 TX 节拍或物理 jerk。发送时间对齐、轨迹和采样尚未真机验收。

### 伺服调试

`ServoTuning` 必须完整包含 `friction_enabled:boolean` 及七个关节的 `kd/velocity_ff/coulomb/viscous/velocity_scale/max_friction`。基线为摩擦关闭，每轴依次为 `10/1/0/0/0.02/0.5`。闭区间范围依次为 `[0,30] Nm·s/rad`、`[0,1]`、`[0,2] Nm`、`[0,10] Nm·s/rad`、`[0.001,0.2] rad/s`、`[0,2] Nm`；拒绝非有限值。

发送端按未缩放的轨迹速度 `v` 计算 `friction=clamp(Fc*tanh(v/epsilon)+B*v, ±max_friction)`，与重力相加后再限制到 ±8 Nm。摩擦关闭或 `v=0` 时摩擦项严格为零；开关不影响独立的速度前馈权重。`velocity_ff*v` 仅用于报文 `dq`，轨迹积分、TCP 路径、停止及收纳返回时序继续使用原始速度。±8 Nm 限制的是附加前馈通道，不能视为电机总输出上限。

持有者通过 `configure_servo` 显式应用整份配置；HTTP 202 表示入队，结果为 `accepted/configure_servo` 或 `rejected`。运动、停止减速和使能确认期间返回 `motion_busy`，连接中/未连接不接受，故障或待清错返回 `fault`。已使能空闲时须取得当前 generation/epoch、新鲜且静止的成功发送目标，复制其位置再应用；配置和 generation 版本提升，旧运动请求失效。认证、租约与停止权限沿用原约定。详见[伺服调试配置](implementation-contract.md#59-伺服调试配置)。

以上前馈计算无内部状态，参数标定与减抖效果尚未真机验证。候选方案与证据见[补偿方案调查](research/motion-compensation-repositories-2026-11-21.md)。

### 状态语义

| 状态         | 含义                                                                    | 可发生的下一步                                |
| ------------ | ----------------------------------------------------------------------- | --------------------------------------------- |
| 未连接       | 无打开的设备会话                                                        | 取得控制、连接、参考模型查看                  |
| 连接中       | 正在建立会话及收集反馈                                                  | 成功、失败或取消                              |
| 已连接未使能 | 端口已打开，设备状态独立报告                                            | 持有者显式使能；断开                          |
| 使能中       | 已发送使能，等待七轴请求之后的新鲜 mode=1、零故障、无超时反馈；一秒期限 | 全部确认后可操作，或停止/确认超时故障         |
| 可操作       | 已使能且基础反馈/配置有效；动作专用条件仍分别检查                       | 当前持有者开始满足条件的一种点动，或停止/失能 |
| 运动中       | 唯一一种关节或末端动作，模式为连续或步长                                | 续输入、完成、停止、故障                      |
| 停止中       | 取消输入并完成控制退出                                                  | 可操作、未使能或故障，不接受新动作            |
| 故障         | 设备/反馈/数值/通信不满足继续条件                                       | 查看原因，持有者清错/断开；不自动恢复旧动作   |
| 关闭中       | 整个应用正在退出                                                        | 撤销动作和控制权、关闭设备与接口、结束应用    |

控制权与反馈有效性是独立字段，不把它们重复编码成多套状态机。只有控制模块能改变控制状态。

使能时从当前有效位置建立初始目标。停止、失能和退出分别执行对应的设备策略，其物理效果列入真机测试。

设备超时状态或运行中退出 mode=1 会锁定故障、取消动作并失能；后续正常反馈不会恢复旧动作。清错须等新鲜、无超时且零故障反馈确认，再由持有者显式使能。

工作台停止可以取消任何客户端的当前动作，保留原控制权归属且不自动失能。取消推进 generation，使旧输入失效，并为原 request_id 产生 cancelled 终态；停止流程未结束时不接收新运动。重新运动仍需持有者显式发起新请求。

同一 Rust 应用里，串口与控制用专用线程，网络使用异步运行时，渲染在 WebView。命令交接有界，状态发送采用最新快照；慢 UI/订阅者不能阻塞电机循环。

arm 独占求解 seed、上个已接受参考和当前目标。kinematics 只计算候选及诊断，由 arm 复核当前反馈、限制、输入和控制权后提交；不让数值模块单独推进另一份动作状态。

普通命令超出容量时明确拒绝；连续输入只保留最新有效序号，停止/退出必须优先送达，不能排在大量旧输入之后。具体通道类型属于 arm 内部实现，不建通用总线框架。

停止在每个控制周期开始、每次 I/O 返回后、候选提交前检查。发送线程在取样后、写入前再检查 epoch、输入/租约有效期和优先命令。I/O 线程批量下发七轴命令，沿用 20 ms 整批写入预算；短写保留帧内偏移，超时/失败进入恢复或故障，不能盲重发整帧，也不能在半帧中插入其它报文。反馈使用连续接收和带时间戳的最新观测，不再每个控制周期清空输入。优先通道本身不能中断阻塞 I/O，时间预算不能保证解除卡死的 OS 调用。

官方模型和标定按左右臂集中打包，带来源信息；前端和后端消费同一份 resources 资源。端口使用枚举/配置，资源使用平台无关路径。当前只支持已提供模型，不增加设备注册或多后端机制。

事件 SQLite 记录连接、控制权、动作、故障及应用事件，不逐帧存储串口或遥测，不记录 token 或 lease。`log` 构造字段长度有界的内存记录，使用 `Mutex.try_lock` 向预分配的 1024 容量队列提交；竞争、锁损坏或队列满立即计 dropped，关闭后提交和退出时放弃的数据也计 dropped。`stats` 只读原子计数，不等待队列、磁盘、SQLite busy 或 writer。writer 轮询取出数据后独立执行 SQL，初始打开和建表也在后台，采用 WAL、批量事务、有限 busy_timeout 和失败退避恢复。后台操作失败增加 errors，pending 包含已接收但未提交的事件，written 统计本进程成功提交的事件。

保留最近 100000 条事件，清理和 checkpoint 均在 writer 执行。`recent` 是阻塞只读接口，server 必须使用 spawn_blocking；按 id 降序、limit 最多 500。`shutdown(timeout)` 仅供应用关闭协调线程有界等待，超时返回失败并请求后台停止；不承诺强制中断 OS 调用，Drop 不阻塞。

日志页读取 SQLite 历史，重启后保留，按 25/50/100 条分页并搜索全库。第一页每 2 秒刷新，翻页沿用 `through_id` 固定记录范围；新增日志不会推移旧页，最近 100000 条保留上限仍生效。时间同时显示日期，分页栏总数与本次运行写入数分开。

短时采样单独存放在 `events.sqlite3.traces.sqlite3`，保留最近 10 次，每次最多接纳前 100000 次样本提交尝试。预分配队列容量为 4096，内联完整伺服配置后样本存储约 5 MiB（不含 writer/SQLite 开销）；生产者使用 `Mutex.try_lock`，竞争或满队列时立即丢弃并计数，路径中无等待、SQL、JSON 编码或分配。独立 writer 轮询并取出数据后执行序列化与 SQLite 写入。采样的 `accepted/written/pending/dropped/errors` 按次统计，与事件 `journal` 统计分开。

## 6. 本机接口 v1

默认仅绑定 `127.0.0.1:8177`；绑定失败应在界面说明并禁用设备操作，不静默改成局域网监听。端口号是应用默认值，不是硬件参数。

| 入口                  | 当前用途                                                                                                                      | 返回的语义                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| GET /v1/ports         | 端口列表和可得的设备信息                                                                                                      | 只读，不打开或使能设备                                  |
| GET /v1/state         | 完整状态快照                                                                                                                  | 当前状态，不用查询成功推断设备健康                      |
| POST /v1/control      | acquire / renew / release                                                                                                     | 控制模块决定后返回结果；控制者获得私有租约凭据          |
| POST /v1/commands     | connect / disconnect / enable / disable / clear_fault / configure_tcp / configure_servo / jog_start / jog_update / step / return_to_pose / stop | 请求入队不等于被控制器接受或设备执行完成                |
| GET /v1/logs?limit=50 | 最近结构化事件                                                                                                                | 按 id 降序，最多 500 条；阻塞读通过 spawn_blocking 执行 |
| GET /v1/logs/page     | 持久化日志搜索与分页；page/page_size/search/through_id                                                                         | 200 {items,page,page_size,total,total_pages,through_id}；spawn_blocking 只读事务 |
| GET /v1/traces        | 最近采样汇总                                                                                                                  | 默认 limit=20，实际限制到 1..10                         |

| POST /v1/traces/stop  | 结束当前采样                                                                                                                  | 200 TraceSummary 或 null；不取消机械臂动作              |
| GET /v1/traces/{id}   | 读取采样 JSON；download=true 下载，attachment=true 为别名                                                                     | 200 {trace,samples}，包含原始来源时间                   |
| WS /v1/events         | 完整快照，包含请求结果和日志统计                                                                                              | 首帧认证后发送状态；掉线后重取快照，不重放运动          |

本机接口使用当前应用会话凭据，控制请求还需有效的私有租约。只读快照只公开控制者标识与有效性，不广播可用于接管的租约凭据。CORS/Origin 不能替代控制权校验；接口信息可查看/复制，凭据不进入日志。

全部采样接口使用同一 Bearer 与 Origin 校验，开始/停止采样无需运动租约，也不申请控制权、打开端口、使能或启动运动。开始要求快照已有端口，且不在 `disconnected/connecting/closing`。采样返回 `recording/writing/complete/failed` 状态，停止记录后可继续写入；完整性需同时检查各计数。样本的 `source` 为 `control/transmit/feedback`，`at_us` 为来源单调时间相对采样开始的微秒数。

`transmit.seq` 仍是源 `control.seq`，重复序号不表示相同位置。`control.q_ref/dq_ref` 保留控制器参考；`transmit.q_ref/dq_ref` 为发送时对齐或回退保持的理想目标，`q_wire/dq_wire/tau_wire` 为实际编码后反标定的关节 SI 值。发送样本增加 `timing:{status,age_us}|null`，表示取样状态和源年龄；旧文件缺省时按 null 读取。完整字段与状态取值见[接口说明](implementation-contract.md#92-样本字段与时间)，路由不变。

控制样本新增可缺省的 `servo_tuning`（完整配置或 null）与 `servo_tuning_revision`（u64），旧文件按 null/0 读取。发送样本新增可缺省的 `tuning:ServoSample|null`，记录配置版本、加权后的 `dq_feedforward`、重力、摩擦请求/实际增量及逐轴限幅标识；旧文件按 null 读取。`transmit.dq_ref` 始终是未缩放的轨迹速度，`tau_ff` 为最终总附加前馈；编码误差应以 `dq_feedforward` 对照 `dq_wire`，旧样本回退到 `dq_ref`。

工作台停止通过主窗口的 Tauri 命令调用 arm，不需要运动租约。外部 HTTP 客户端的停止权限按控制权校验：持有者可以停止自己的动作，其他客户端保持只读。

HTTP 在请求头中携带应用会话凭据；WebSocket 升级后首帧认证，认证成功前不发送快照，认证等待有时限且连接数有界。凭据不进入 URL。浏览器 Origin 白名单与应用凭据分别检查，不用其中一项替代另一项；不建立用户账户系统。

租约期限由 arm 的单调时钟裁决，时长与续期间隔是明确配置。释放或到期时同时取消动作并推进 generation；迟到续租不能复活旧租约。控制线程应用命令与提交运动候选前，必须复核租约及 generation。

首版通过旧持有者 release、另一客户端 acquire 显式交接；持有期间拒绝他人的 acquire。先结束旧动作的控制流程，才允许新持有者发起运动。工作台聚焦、重连或点击点动都不能隐式取回控制权。

### 状态与命令的数据格式

| 数据         | 必需信息                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 上下文       | side、port、TCP 配置状态、控制者、generation、快照序号                                                   |
| 伺服配置 | servo_tuning 完整配置、servo_tuning_revision 当前版本；每次连接/断开恢复基线 |
| 实测关节     | 固定七个关节的名称/ID、q/dq/tau、逐关节 age_ms、可得的温度/电压/error；无反馈字段为 null                 |
| 反馈计算 TCP | 当前关节快照经当前模型/TCP 的 FK 结果；TCP 未配置或无有效完整反馈时为 null，四元数为 x/y/z/w             |
| 动作         | space、mode、axis、request_id、progress；last_result 与有限 results 保存请求结果和原因                   |
| 请求         | request_id、客户端标识、必要租约、预期 generation、动作空间和专用参数                                    |
| 连续输入     | jog_start 给出 space/axis/direction/speed/frame；jog_update 仅用 action_id/input_seq/ttl_ms 续期现有动作 |
| 日志统计     | pending、written、dropped、errors、healthy，控制线程只读原子值                                           |

generation 在连接重建、模式/TCP/伺服配置改变、停止、动作完成、控制权失效等上下文变化时推进。input_seq 按租约、generation 和当前动作校验；续输入只更新显式开始的当前动作，不能隐式创建动作。快照序号只表示观测顺序，不代替上述上下文。

连续输入的截止时间在后端首次接收时用单调时钟确定，排队、重试和出队均不延长；每周期先处理取消，再计算和最终复核候选。停止后迟到的旧输入不能重新启动动作。

age_ms 由后端单调时钟计算；前端叠加接收后经过的时间作过期显示。关节接收时间跨度只描述主机收到反馈的情况，不表示七轴同步采样。反馈计算 TCP 来自当前关节快照与当前模型/TCP，不是独立 TCP 传感器的实测值。

POST /v1/commands 只先返回入队结果。accepted 指控制线程复核后建立该动作；rejected 指未建立。末端步长 completed 要求段结束，且新鲜反馈的 FK 结果在位置/角度容差内；关节步长以实测关节误差容差判定。写串口或 flush 成功都不能代替完成判据。连续动作由取消或失败结束，不把松开等同于“已停稳”。

已接受动作遇停止、换代或故障时，产生关联原 request_id 的 cancelled/failed 终态。步长在当前会话/generation 内至多执行一次；完成或取消后推进 generation，并保留有限最近结果供查询。迟到重复请求不能重启旧动作；不承诺跨进程重启的 exactly-once。超时或重连后查询状态，不自动重复发送旧运动。

错误至少区分参数无效、非控制者、上下文过期、设备未就绪、反馈过期、运动忙、队列满、数值无法继续、应用关闭中。错误包含原因与请求关联，不把所有失败都化成网络错误。

### 集中配置与验证的参数

初始步长建议为 1 mm / 1°，实际运动精度列入真机测试。设备配置集中给出线/角速度、关节速度、加减速与 jerk、最大局部增量、位置/角度容差、参考相对实测的偏差、反馈年龄/接收跨度、输入有效期、租期、I/O/退出预算、控制周期与阻尼/奇异尺度。配置必须有限、单位明确且内部一致；不能用无穷大、缺失值或 parser 默认代替动态限制。

协议默认波特率为 6 Mbps，串口和转接器支持情况列入真机测试。参数类别、单位和失败行为由本规格定义；配置按模型和报文预算实现。执行动作前检查所需配置。

## 7. 退出行为

关闭主窗口时，先由控制线程检查当前保持状态。已使能或正在使能时，保留连接并在主窗口提供收纳后退出或确认已有支撑后退出的操作。收纳使用记录的实测七轴位置，限速返回并稳定到位后才断开；取消或失败不会继续退出。确认退出后，后端进入关闭中，停止接单，撤销控制权并使旧输入失效，取消当前动作并尝试执行设备退出策略。正常路径回收串口和控制线程，再结束本机接口与应用。当前动作即使由外部服务发起，也随应用退出取消。

设备无响应或 OS I/O 异常时，界面/诊断记录失败或未知，不报告“机械臂已停稳”。退出不无限等待 flush 或 join；超过已配置宽限期时记录设备结果未知并结束进程，不能同时报告线程已回收或输出已排空。具体预算在实现/验证中固定，软件退出上限不能当作物理停稳时限。

## 低速稳定性校准（2026-11-22）

控制页“校准”直接打开测试弹窗。点击开始后，程序保存当前保持目标作为原位，逐轴执行 ±2°、1°/s 与 2°/s 的往返；针对误差较大的两轴分别比较摩擦与速度前馈，再合并参数测试全部轴。无需填写参数、归绝对零位或等待反馈速度归零。Kp/Kd 保持不变；参考和实测均限制在起始姿态各轴 ±4° 范围内。

使用 100 ms 位移窗口统计位置及速度跟随误差，并每 20 ms 记录七轴控制参考、成功发送目标、原始反馈及时间。综合比较使用速度 0.6、位置 0.4 的相对误差，没有固定改善百分比门槛。无改善也是正常完成，保留测量供比较。

测试复用受限收纳轨迹、控制权、停止与故障处理。正常结束回原位并恢复起始配置，有推荐时显式应用；停止则取消后续动作、减速并恢复参数，不继续回原位。普通保持连接的收纳返回在指令到位后完成；到位断开额外按七轴位置容差 0.02 rad 和 200 ms 新反馈判断，反馈 dq 不参与到位判断。实际未到位时保持使能并显示偏差。

SQLite 异步保存最近 100 份报告和时间曲线；状态流与历史列表只发摘要。弹窗可按轴查看位置、速度、跟随误差及前后对比，导入旧报告或下载完整 JSON，适配 800×560 内容区。实现与试用步骤见[校准测试计划](low-speed-calibration-test-plan.md)，字段见[API 5.10](implementation-contract.md#510-低速稳定性校准)。本轮尚未真机验证。
