# 一天内由 Agent 推进的 MVP 范围与验收

日期：2026-11-09。本文是实施计划评估；用户仍要求先不写代码，本轮未创建控制器、Cargo 项目、测试程序或原型。

后续状态：用户已要求技术与原型定稿，当前唯一有效的实施基线见[规格 1.0](../spec.md)。本文保留当时的研究与预算依据，不继续作为未决选型或原型状态说明。

## 目标与当前条件

用户选择的最终验收目标是单平台真机端到端 MVP，其余平台实机验证另算；当前机械臂与 USB 转接器不可访问，先在当前系统验收，并保持代码可维护和跨平台。

当前系统经只读检查为 **macOS / arm64**；Rust 1.99.0、Cargo 1.99.0、Node.js 26.10.0 可执行，Xcode Command Line Tools 路径已存在。这些是工具存在和版本证据，尚不是 Tauri 应用构建成功证据。[Tauri 桌面前置条件](https://v2.tauri.app/start/prerequisites/)

因此，一天预算内可争取的可检验交付是 macOS 上的可运行软件 MVP、离线协议与模型验证、界面和本机 API 联调。**最终真机目标仍保留；在没有设备访问的条件下，不能将它记作验收完成。** 不把模拟关节、录制样本或模型运动标成实测反馈。

## 当前选型建议

**针对当前固定七轴、小范围连续/步长点动，建议优先采用 `serialport 4.10.1 + nalgebra 0.35.0 + urdf-rs 0.10.0`，由一个内聚的运动学模块实现有限的 FK、TCP Jacobian 和加权局部阻尼步。** 不把 k 放进默认依赖，不为一天目标维护 k 的升级分支。

理由是当前需求并非通用机器人求解系统：矩阵、分解、四元数与模型解析都有库；项目需要自己掌握的是坐标、当前 TCP、连续性、限幅与失败行为。这些控制策略即使采用现成 IK 仍要处理。直接实现减少旧版类型耦合和新框架适配，但把有限算法的正确性与验证责任留给本项目。

若选择现成数学内核，**Caliper 的独立 crates 小组合**是本轮最有证据的备选：它确有通用 Jacobian、seed IK、专门七轴测试和一次成功的核心 CI。多个依赖 crate 本身不等于应用代码拆散；不把它列为首选的依据是当前功能不需要它的完整 IK 行为、部分旧依赖仍在、维护历史较短，且实际接入尚未验证。这个比较不意味着自行实现必定更快，也不意味着 Caliper 不可用。

当前推荐仍是评估结论，未创建依赖清单或启动编码。实施开始时只固定并实现一条路线，避免多引擎及兼容抽象。

## 为什么重新评估 k

旧版本本身不能证明不可维护。当前已知的具体成本是：k 0.32.0 稳定版发布较早，要求 nalgebra ^0.30、urdf-rs ^0.9；直接使用当前数学/模型库会遇到版本和类型隔离，需要沿用旧版、转换或自行维护兼容改动。近期一次开发依赖更新也不能证明控制算法一直有持续修复。[发布 manifest](https://docs.rs/crate/k/0.32.0/source/Cargo.toml)、[发布记录](https://crates.io/api/v1/crates/k)

k 已提供的 FK/Jacobian/局部 IK 仍有参考和测试对照价值。此前“先评估 k”不等于决定引入它；也不建议在一天预算中同时承担库升级分支与控制器集成。

活跃替代库与直接 nalgebra 的专项证据分别保存在 [活跃库调查](active-rust-kinematics.md)和 [直接 nalgebra 评估](nalgebra-direct-assessment.md)。近期提交只是维护信号；本项目还要判断它是否降低当前七轴功能的接入和验证工作。

## 现成替代库的实际比较

| 候选 | 相对 k 的新进展与现成能力 | 维护与接入保留意见 | 当前建议 |
|---|---|---|---|
| Caliper 小组合 0.2.1 | 2026-07 发布，nalgebra ^0.35；URDF、FK、公开 6×N Jacobian、seed IK；有专门 7DOF 测试，所读核心 CI 成功 | 当前只有一轮发布、单一公开 crate owner，最近代码提交为 2026-07-31；model 仍依赖 urdf-rs ^0.9；默认 IK 有随机重启，连续运动要关闭/约束它并验收增量 | 最值得认真比较的现成库备选 |
| ferromotion-core 0.73.0 | 2026-09 发布，最近代码提交到 10 月；URDF、FK、Jacobian、LM/seed IK | core 功能和依赖面较广，便利 IK 不自动保证硬限位；发布之后的 main 最近 CI failure，未取得具体原因，不能据此判定发布版坏了 | 本次不优先承担其额外排查 |
| Optima 0.0.4 | 已有通用模型、FK/Jacobian 和 IK | 发布在 2022 年、核心提交更旧，使用旧数学/模型依赖及非 optional PyO3 | 不作为更活跃、更轻的替代 |

Caliper 的最小复用面应比较 model/spatial/kinematics/ik 独立 crates，而非直接引入 umbrella；但是否净省工作还取决于实际模型和控制接入。本次只调查，未构建这些候选。证据：[Caliper API](https://docs.rs/caliper-ik/0.2.1/caliper_ik/fn.ik.html)、[七轴测试源码](https://docs.rs/caliper-ik/0.2.1/src/caliper_ik/lib.rs.html)、[成功的核心 CI](https://github.com/msannikov03/caliper/actions/runs/30656371909)、[Ferromotion 发布依赖](https://crates.io/api/v1/crates/ferromotion-core/0.73.0/dependencies)。精确时间、提交、CI 范围与筛除候选见[专项报告](active-rust-kinematics.md)。

本次范围内没有发现一个在成熟度、维护连续性、轻量接入与当前需求上都明显占优的现成替代；这不构成对全网所有 Rust 库的排除结论。

## k 与直接 nalgebra 的维护成本

| 维度 | 继续使用 k | 直接 nalgebra + urdf-rs |
|---|---|---|
| 已有能力 | 库提供通用链、FK、Jacobian 与局部 IK | 库提供矩阵、变换与模型解析；项目负责当前七轴的有限算法 |
| 版本依赖 | 需要使用 k 兼容的旧版 nalgebra/urdf-rs，或自行维护迁移 | 当前 0.35.0/0.10.0 可直接组合，没有 parser 传出旧数学类型的问题 |
| 数值策略 | 要适配库的迭代、clamp 和失败行为，再实现连续控制 | 直接围绕局部 DLS 的输入、预算、限幅和失败结果设计 |
| 所有权 | 上游控制核心框架，项目负责集成和控制行为 | 项目拥有小范围 FK/Jacobian/局部步的正确性与维护 |
| 验证 | 仍要验证当前模型、坐标和连续运动，不因用了库而省略 | 同样需要独立对照与行为验证，并直接覆盖自写算法 |

nalgebra 与 urdf-rs 的版本和依赖事实来自[专项报告](nalgebra-direct-assessment.md)的已发布清单。报告核查了固定尺寸矩阵、Cholesky/SVD 与几何 API，没有运行本项目依赖解析或编译。

对当前固定七轴的小范围点动，直接 nalgebra 的维护面可以控制在一个内聚的运动学模块；它的优势是模型、约束与失败行为透明，代价是必须由项目承担验证。不能仅凭“更少依赖”就宣称自写实现一定比成熟库更正确。

## 缩小到当前真正需要的算法

首版需要的是从当前构型开始的局部六维点动，不要求任意远端目标的全局 IK、抓取规划、机器人动力学或完整路径规划器。

| 当前能力 | 有限实现范围 | 必须检查的结果 |
|---|---|---|
| URDF 与 FK | 当前七轴串链、固定连接、轴与 origin、实际 TCP | 关节名/顺序、方向、单位、左右模型和已知姿态 |
| 几何 Jacobian | 当前 TCP 点的 6×7 矩阵 | 与 FK 有限差分对照，覆盖非零 TCP 与非 identity 基座 |
| 连续点动 | 在统一参考系中把局部速度变成有界关节增量 | 动态限幅、构型连续、反馈过期、输入失效与停止 |
| 固定步长 | 将一次末端增量形成连续目标段，用同一局部求解路径跟随 | 路径中间过程与终点残差，避免只求终点后关节插值 |
| 近奇异与数值异常 | 带尺度约定的分解/阻尼、步长与关节增量验收 | 降速或停止，并明确失败原因 |

当前 nalgebra 已提供纯 Rust 矩阵分解、线性系统求解和几何运算；这些可以复用。URDF 到模型、FK/Jacobian 的约定和控制行为仍由本项目负责，不能把数值库等同于机器人控制库。[nalgebra 分解说明](https://www.nalgebra.rs/docs/user_guide/decompositions_and_lapack/)

上一已接受解作为附近目标的求解起点，是数值 IK 的常见局部策略；它不保证全局可达。微分点动和全局 IK 应按当前需求分别判断。[Modern Robotics 数值 IK](https://modernrobotics.northwestern.edu/nu-gm-book-resource/6-2-numerical-inverse-kinematics-part-1-of-2/)

## 并行 Agent 的分工

先由主 Agent 固定小范围的模块输入输出和数据约定，再让三个工作 Agent 并行修改互不重叠的文件，主 Agent 持续集成。保持单个应用，代码按实际职责组织。

| 角色 | 拥有的工作 | 合并前提供的证据 |
|---|---|---|
| 主 Agent | 控制模块的权威状态、单一控制权、本机 API、应用退出与集成 | UI 与外部调用同一组操作；异常与退出结果一致 |
| 通信 Agent | 当前协议编码/解码、CRC、标定与串口接入 | 官方参考数据对照、部分包/错包恢复、错误传播 |
| 数值 Agent | 当前模型、FK、Jacobian、局部求解和数值检查 | 独立参考姿态、Jacobian 有限差分、限位与奇异场景 |
| 界面 Agent | 单页工作台、模型加载、点动交互与状态展示 | 当前 macOS 上界面可运行、模型资源完整、状态来源明确 |

协议编码器可以离线使用官方实现作为测试参考或夹具来源；它不进入产品运行依赖。测试数据生成、数学检查和 UI 演示不代表机械臂已经反馈或执行。

这次只安排方案，不实际派发实现任务。用户授权实现后，Agent 才按这些写入范围工作；不创建新的用户聊天、后台定时任务或额外产品模块。

## 一天的执行预算

下表按实施启动后最长 24 小时的工作窗口分配预算，**不是已测量工期，也不是必然完成保证**。当前没有开始实施计时；上一轮人工“人日”估算不直接换算为 Agent 日历时间。

| 相对时间 | 工作与收敛点 |
|---|---|
| 0–1 小时 | 确认接口/模型/坐标约定、锁定依赖与验收样本，建立最小构建 |
| 1–5 小时 | 三个 Agent 并行做协议、数值、界面；主 Agent 完成控制状态与 API |
| 5–10 小时 | 集成实际调用链，校验模型坐标、点动输入、控制权与退出行为 |
| 10–16 小时 | 补充独立数值/协议对照与异常检查，修复当前平台构建和资源问题 |
| 16–24 小时 | macOS 打包与回归，整理已通过/未通过证据，为阻塞问题留余量 |

最迟在第一阶段结束时固定一条运动学实现路线，不同时实现多个可切换引擎。发生依赖/构建/数值阻塞时先收敛当前实现；时间预算不能作为跳过关键验证的理由。

## 软件验收与真机验收

| 软件侧可由 Agent 在当前主机完成 | 当前无法完成的真机证据 |
|---|---|
| Rust 后端与桌面可构建、启动、退出 | 厂商转接器在当前 macOS 的真实 6 Mbps |
| 协议输出与参考一致、解析能恢复同步 | 七关节新鲜反馈、ID/标定与本体的实际一致性 |
| FK/Jacobian/局部求解通过独立模型检查 | 实际 TCP、负载下的跟随和停止表现 |
| UI 加载官方模型，状态来源和过期可辨识 | 真实关节驱动的 3D 与低速六维运动 |
| 本机 API 控制权、取消、停止和退出可测 | 热拔插、超时、重连后的真实总线和电机行为 |

测试夹具只服务当前验证，不引入可扩展的虚拟设备框架。没有真实有效反馈时，应用不宣称已连接/可运动；开发演示数据与设备实测状态在显示和接口中明确区分。

## 保持跨平台和高内聚

- 串口统一调用 serialport 已有平台实现，端口来自枚举或显式配置；资源使用平台无关路径解析。
- URDF 与标定集中管理，控制模块只有一份设备状态与运动规则；本机 HTTP/WebSocket 与 UI 调用同一组操作。
- 数值计算集中在一个小的运动学模块，通信协议集中在一个协议模块；不为未知硬件建立 trait 层次或插件系统。
- 控制循环与网络/渲染调度分开，使用有界命令与状态交接；退出由同一应用所有者管理。
- 当前只验收 macOS；Windows/Linux 的构建与实机证据单独记录，不把可移植代码称为三端已通过。
