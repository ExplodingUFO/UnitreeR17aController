# 点动抖动与旋转中心调查

日期：2026-11-21。代码基线：`4539745bcf97e38cbfde1b75062e90c6f14f3db3`，从 `origin/main` 快进拉取。用户测试条件为 macOS、右臂、无外接负载，底座平放、机械臂向上立装，关节和末端点动均出现抖动。

目前确认两个可离线复现的软件问题：串口发送节拍不均，以及最大角速度下末端运动被速度检查中断。两项已有本地修正。物理抖动还需要用修正前后的真机数据对比；本轮没有连接串口或执行机械臂动作。

## 1. 串口发送节拍不均

控制计算与串口发送已经分为两个线程，但原发送线程有两套时序：

- 无新目标时，从上一批七轴报文**发送完毕**起等待 10 ms，再发保持心跳。
- 收到新目标时，把计时器直接设为到期，立即发送。

新目标若紧跟心跳到达，两个批次就会挤在一起。声明控制循环为 100 Hz 并不能保证实际发送批次均匀。

复现使用生产 `BusHandle` 和内存中的 `FakePort`，记录每批 J1 写入调用的开始时间。测试不打开系统串口。

| 检查            | 相邻批次间隔         |
| --------------- | -------------------- |
| 修正前，第 1 轮 | 13.014 ms、2.938 ms  |
| 修正前，第 2 轮 | 12.139 ms、2.827 ms  |
| 修正后，第 1 轮 | 10.541 ms、10.157 ms |
| 修正后，第 2 轮 | 10.334 ms、10.554 ms |

修正后，新目标只替换下一批的内容，不重置发送时钟；周期从批次开始计算。延迟后合并为最新目标，不连续补发积压目标。停止与清错仍使用各自的优先写入路径。

复查命令：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib serial_target_update_after_heartbeat_preserves_send_period --locked -- --nocapture
```

这些数值测量的是主机发送线程调用时刻。USB 转接器内部缓存和 RS-485 线上的实际时刻需要另行测量。

## 2. 最大角速度触发运动中断

在仓库记录的右臂安装姿态下，基座 Rx 连续点动设置为允许的最大值 `0.15 rad/s`，原实现运行到第 24 个采样点时返回 `final FK increment exceeds TCP speed limits`。前端会收到动作失败，该输入不会自动恢复。

原求解先用 Jacobian 约束瞬时速度，再检查实际 FK 位移。瞬时速度贴着上限时，非线性有限步进会略微超出最终检查阈值。

修正为在统一任务缩放时预留 0.1% 的速度余量，而非只在瞬时速度已经越界后缩放。仍检查最终 FK、关节速度、加速度和参考偏差。新增回归测试连续运行 200 个采样点。

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib rotation_jog_at_maximum_speed_does_not_interrupt --locked
```

这说明部分中途停止来自软件检查，不等于所有速度下的持续振动都来自此处。

## 3. 工件旋转与 TCP

用户期望的是：把工件上的某一点设为旋转中心，改变工件姿态时保持该点的位置。该点应定义为 Link7 到 TCP 的工具变换。

当前连接默认使用单位变换，即 TCP 位于 Link7 坐标原点。工件中心需要按实际安装另设偏移；Link7 原点也不能直接等同于法兰端面中心。绕当前 TCP 或工具轴旋转时，主要由腕部关节完成可以是正确解；求解器不要求每次旋转都让七个关节明显运动。

设置非零 TCP 偏移后，保持的是偏移后的点。比如在 Link7 坐标系中设置 `Z=100 mm`，绕工具 X/Y 轴旋转时，法兰必须平移来补偿。如果围绕与偏移共线的工具 Z 轴旋转，法兰不需要这种平移补偿。

本轮用右臂模型、`5°/s`、100 Hz、2 秒的理想跟随测试验证：

| 设置                                  | 结果                                         |
| ------------------------------------- | -------------------------------------------- |
| 法兰前方 100 mm 的 TCP，工具 Y 轴旋转 | 法兰移动约 16.826 mm，TCP 漂移约 0.011907 mm |
| 同一 TCP，工具 X 轴旋转               | 法兰移动约 16.509 mm，TCP 漂移约 0.005592 mm |
| 基座与工具的三个旋转轴                | 均通过旋转方向、TCP 漂移及关节动态约束检查   |

这是模型内部的计算误差，不是机械臂的实测精度。实际 TCP 的方向、距离、安装零位和关节跟随误差仍影响工件运动。

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib rotation_jog_preserves_selected_tcp_and_axis --locked -- --nocapture
```

## 4. 阻塞、增益与机械因素

正常点动时，控制线程发布最新目标，由独立发送线程下发；接收线程采集反馈。SQLite 使用专用后台写线程，提交日志使用有界 `try_send`。本轮未发现正常点动在控制线程等待 SQLite 提交的路径。清错、断开和关闭存在单独的有界等待路径，应与持续点动区分。

当前伺服指令包含位置、速度、扭矩前馈及 `kp/kd`。主机没有一个可直接调整的积分 I 项。`kp=60`、`kd=10` 不能单独决定整个系统是否平稳；目标连续性、设备内部速度估计、重力补偿和安装条件同样参与实际响应。

当前重力计算使用模型基座坐标中的 `g=[0,0,-9.81] m/s²`，基座 `+Z` 朝上，使用 URDF 中的质量和质心，逐轴前馈限制为 ±8 Nm。用户已确认底座平放、机械臂向上立装，与该重力方向一致，本次无需调整安装方向参数。方向一致不代表重力补偿幅值已经过实测校准；无外接负载也仍有机械臂自身重量。

当前末端求解以关节参考姿态计算 FK/Jacobian，实测关节主要用于参考偏差约束。若参考与实测偏差较大，数学上的旋转中心与实物上的旋转中心会产生差别。离线条件性反例中，J2/J4 分别相差 0.20/0.10 rad 时，同一参考速度在实测姿态处的 Jacobian 预测出 3.87° 轴偏差和 4.61 mm/s 横向速度。这说明大跟随误差会破坏实物的旋转效果，但不能据此认定本次实物存在同样误差。

### 与官方实现的对应关系

对照低层 SDK `0803d033b530fcfa0e6fa9236de68c2773fc9402` 与官方遥操作 `e2faf3ec17f589db2139c51b020592a4a05f836b`：

| 项目                       | 核对结果                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| 位置、速度、扭矩和增益编码 | 齿比及增益平方换算一致，未发现单位换算错误                                                 |
| `kp=60/kd=10`              | 与官方遥操作 CLI 默认值一致；调度、轨迹整形仍有差别                                        |
| 运动时的 `dq`              | 官方同样发送目标速度；当前没有依据把速度前馈统一改成零                                     |
| 重力前馈                   | 指令姿态、保持力矩符号与 ±8 Nm 限幅的原则一致                                              |
| 无负载右臂模型             | 当前使用裸臂质量；官方遥操作另外加了 Dex1 夹爪，不能直接复制其完整负载参数                 |
| 上游轨迹                   | 官方另有位置/速度/加速度整形及 jerk 限制；当前关节点动只限制速度、加速度，轨迹策略并不相同 |

官方运动路径按最终下发位置的差分和实际时间生成 `dq`。当前 `dq` 对本地积分的参考位置是一致的，但原发送节拍不均仍会改变设备实际看到的目标时序。官方标定样例与本地一致，也不等于已校准这台机械臂的零位和安装方向。

编码还存在与官方相同的速度量化：J1–2、J3–5、J6–7 每档约为 0.003068、0.007751、0.006136 rad/s。细小关节速度在阈值附近可以跳档；这只是协议层事实，尚未测得它在真机上造成的扭矩振动。

## 5. 日志覆盖与新增测量

本机现有 SQLite 只有 32 条历史事件，截止 2026-11-10，没有这次 11 月 21 日的运动或 `control/cycle` 记录。它无法用于判断本次抖动频率、自动取消、供电变化或伺服增益是否合适。

原 `control/cycle` 只记录控制计算周期，不记录实际发送批次间隔。本轮补充了：

- 每个诊断窗口的实际发送批次数、间隔平均/最小/最大值、整批写入最大耗时。
- 最大参考偏差关节的指令速度、重力前馈及实测电压。

仍约每秒汇总一次，由 SQLite 后台线程写入；不是逐帧写数据库。统计窗口可重置，接收、CRC 和超时累计计数保留。

这些记录能检查发送节拍和参考偏差，但不能恢复完整的关节运动曲线或确定振动频率。若修正后仍抖，下一步需要短时记录带时间戳的各轴目标位置、实测位置、速度和扭矩，再决定是否调整阻尼或加入滤波。

下一次对比应使用同一姿态、同一轴、同一速度，确认连续输入是否被取消，并同时查看控制周期、发送周期和跟随误差。若指令已连续而实测仍周期性振荡，再按轴评估阻尼、速度估计噪声、摩擦或结构共振。jerk 限制、低通或陷波应针对测得的现象选择，当前没有足够数据支持加入某个固定频率的滤波器。
